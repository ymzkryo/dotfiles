# agy（Google Antigravity CLI）

Google Antigravity の CLI を使用してコードレビュー・分析を実行するスキル。
`codex` スキルと同じ用途で、別のモデル系（Gemini 3 系ほか）の見解が欲しいときに使う。

> **バイナリ名は `agv` ではなく `agy` です。** `antigravity` でもありません。
> 未導入の場合は `agy` が見つからず失敗するので、まず `which agy` で確認すること。

## 実行コマンド

```sh
cd /path/to/project
agy -p "<request>" --sandbox --print-timeout 15m
```

`-p`（`--print` / `--prompt`）が非対話の単発実行にあたる。**作業ディレクトリを指定する
フラグは用意されていない**ため、対象プロジェクトへ `cd` してから実行する。

## パラメータ

| パラメータ | 説明 |
| --- | --- |
| `-p "<request>"` | 単発のプロンプトを非対話で実行し、結果を出力する（`--print` / `--prompt` も同義） |
| `--sandbox` | ターミナルサンドボックスを有効にし、エージェントが起動するコマンドを OS の封じ込めに制限する |
| `--print-timeout <duration>` | 応答を待つ上限。**既定は 5m** で、規模の大きい依頼では足りない |
| `--output-format <fmt>` | `text`（既定）／ `json` ／ `stream-json` |
| `--model <slug>` | モデルを固定する。候補は `agy models` で確認する |
| `--effort <low\|medium\|high>` | 推論の強度 |
| `--agent <name>` | エージェントを選ぶ。候補は `agy agents` で確認する |
| `--json-schema <string\|path>` | JSON Schema で出力構造を縛る |
| `-c` / `--continue` | 直近の会話を再開する |

### 権限の扱い

レビューや調査では **`--dangerously-skip-permissions` を付けない**こと。これを付けると
すべてのツール要求が自動承認され、ファイルを書き換えられる可能性がある。

非対話（`-p`）では確認プロンプトが出せないため、**承認が必要なツールは既定で
ソフト拒否される**。つまり素の `-p` 実行はおおむね読み取り主体で動く。加えて
`--sandbox` を付けると、エージェントが起動するローカルコマンドも封じ込められる。

設定側の `toolPermission` は `request-review`（既定）／ `proceed-in-sandbox` ／
`always-proceed` ／ `strict` の4つ。`enableTerminalSandbox` の既定は `false` で、
`--sandbox` はこれを起動時に上書きする。

## プロンプトのルール

**重要**: agy に渡すリクエストには、以下の指示を必ず含めること：

> 「確認や質問は不要です。具体的な提案・修正案・コード例まで
> 自主的に出力してください。」

## 長文リクエストの安全な渡し方

**依頼文はファイルへ書き出してから渡します。** 書き出しには Write ツールを使い、
シェルのヒアドキュメントやリダイレクトを経由させないこと。
ファイルの末尾には「確認や質問は不要です。〜」の定型文を含めます。

```sh
cd /path/to/project
agy -p "$(cat <依頼文のファイル>)" --sandbox --print-timeout 15m
```

ダブルクォート内のコマンド置換は結果を再解釈しないので、`$`・バッククォート・
`EOF` などがそのまま 1 つの引数として渡ります。

### ヒアドキュメントの本文へ直接書かないこと

`REQUEST=$(cat <<'EOF' ... EOF)` の本文へ依頼文を**直接書き込む**と、依頼文に
単独行の `EOF` が含まれたときそこで終端し、**続きが親シェルのコマンドとして
実行されます**。引用付きの終端（`<<'EOF'`）でも防げません。コードやスクリプトを
引用する依頼で踏みます。

一方、`$DIFF` のように**変数経由で埋めるのは安全**です。終端の判定は展開より
先に行われるため、変数の値に `EOF` 行があっても終端しません。値の中の `$` や
バッククォートも再評価されません（展開は 1 パス）。

危ないのは「本文へ直接書く」形だけです。依頼文はファイルへ書き出して
`"$(cat <file>)"` で渡すか、変数へ入れてから埋めてください。

依頼文を引数へ直接書くのも避けてください。`$HOME` は値に置換され、
`` `id -un` `` はコマンドとして実行されます。

## agy へ渡す資料の置き場所

会話の中にしかない情報を判断材料にしてほしい場合は、ファイルへ書き出してから
パスを伝える。**書き出しには Write ツールを使い、`cat > <file> <<'EOF'` の形は
使わないこと。** 資料に単独行の `EOF` が含まれると、上記と同じ経路で親シェルの
コマンドが実行される。

**資料は外部（Google）へ送られる。** 認証情報や個人情報は書き出さないこと。
使い終わったら削除する。

リポジトリ内へ置くなら、先に `git check-ignore <dir>` で無視されるか確認する。
**`local/` はこのリポジトリでは無視されていない**（exit 1）。コミットに乗せたく
ない資料は `.gitignore` へ追加するか、scratchpad へ置く。

依頼文の中で「この資料が一次情報である」ことと、各資料の性質（正確なもの／
誤変換を含むものなど）を明示すると、突き合わせの精度が上がる。

## 実行手順

1. `which agy` で導入済みか確認する（未導入ならその旨を伝えて止める）
2. ユーザーから依頼内容を受け取る
3. 対象プロジェクトのディレクトリを特定する（デフォルト: 現在のワーキングディレクトリ）
4. 判断材料がリポジトリ外にある場合は `local/` へ書き出す（→ 上記）
5. **プロンプト末尾に「確認や質問は不要です。具体的な提案・修正案・コード例まで自主的に出力してください。」を必ず追加する**
6. 上記コマンド形式で agy を実行する
7. 結果をユーザーに報告する

### 実行時間について

`--print-timeout` の既定は **5m**。リポジトリ全体を読ませるようなレビューでは
足りないことがあるため、`--print-timeout 15m` のように延ばしておく。

長くかかりそうな依頼は、はじめから `run_in_background: true` で投げて完了通知を
待つほうが確実。途中経過が出ないまま無反応に見えても、異常と判断しないこと。

## 使用例

### コードレビュー

```sh
cd /path/to/project
agy -p "このプロジェクトのコードをレビューして、改善点を指摘してください。
確認や質問は不要です。具体的な提案・修正案・コード例まで自主的に出力してください。" \
  --sandbox --print-timeout 15m
```

### バグ調査

```sh
cd /path/to/project
agy -p "認証処理でエラーが発生する原因を調査してください。
確認や質問は不要です。原因の特定と具体的な修正案まで自主的に出力してください。" \
  --sandbox --print-timeout 15m
```

### 構造化出力で受け取る

```sh
cd /path/to/project
agy -p "このリポジトリの TODO をすべて列挙してください。
確認や質問は不要です。" --output-format json --sandbox
```

## codex スキルとの使い分け

| | codex | agy |
| --- | --- | --- |
| 提供元 | OpenAI | Google |
| 作業ディレクトリ | `-C <dir>` で指定できる | フラグがないので `cd` する |
| 読み取り専用 | `-s read-only` | `-p` の既定（承認要求はソフト拒否）＋ `--sandbox` |
| タイムアウト | 既定なし | `--print-timeout` 既定 5m |

同じ依頼を両方へ投げて見解を突き合わせると、片方の思い込みに気づきやすい。
